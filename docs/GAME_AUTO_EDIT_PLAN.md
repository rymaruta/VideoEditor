# ゲーム実況の全自動編集 計画書

ロケバラエティ向けに作った全自動編集(`VARIETY_AUTO_EDIT_PLAN.md`)を、ゲーム実況の動画にも使えるようにする。
**最優先は「面白い所だけ残す」こと**(利用者の指定、2026-10-07)。

## 前提(利用者への聞き取り)

収録の形は次のすべてに対応する。

| 収録の形 | 中身 | 今のアプリでの扱い |
| --- | --- | --- |
| OBS で画面+声を1本 | ゲーム画面とゲーム音・自分の声が1つの動画 | そのまま読める(カメラ1台として扱う) |
| OBS で音声トラック別 | 1つの動画に、ゲーム音・マイク・Discord などが別トラック | **未対応**(1本目のトラックしか読まない) |
| 顔カメラが別ファイル | Web カメラ・スマホの顔の動画 | 同期はできるが、ワイプとして出さない(隠したまま) |
| 複数人のコラボ | Discord の通話。Craig などで1人ずつ別の音声ファイル | 音声だけのファイルはマイクとして同期される |

仕上がりは3つ: **YouTube の本編(横長・10〜30 分)**、**ショート・切り抜き(縦長・15〜60 秒)**、**配信アーカイブの軽い整え**。

## ロケとの違い(判定の考え方)

- 面白い所の印は「叫び・大声(本人の普段の声からの跳ね上がり)」「笑い」「ツッコミ・掛け合い」「驚き・悲鳴」。
  ゲームの音(爆発・効果音)だけが大きい所は、声が伴わなければ印にしない(ゲーム音は常に鳴っている)
- 落とすのは「黙々とプレイ」「ロード・メニュー・装備の整理」「同じ説明の繰り返し」「離席・待機」
- 声の無いプレイの絵は、ロケの料理の寄りと違って見せ場ではないことが多い。絵として残す長さは短くする

## フェーズ

### G1 · 番組の種類と面白い所の判定(最優先) — 済

- 新しい回を作る画面で、番組の種類(ロケ / ゲーム実況)を選ぶ。種類で判定・カット・テロップの既定を切り替える
- 声の盛り上がりを検出する: 話者ごとの声の大きさを、その人の普段の声(前後 1 分の中央値)からどれだけ上がったかで見る。
  笑い(AudioSet の分類)も数える。AudioSet の「叫び・悲鳴」の分類は、実際の叫び声で閾値を合わせられるまで使わない
- 場面の点数と AI への頼み方をゲーム実況向けにする
- **合格**: 正解の分かる合成の実況素材(普段の話し声の中に、叫び・笑いの山を時刻を決めて入れたもの)で、
  山のある場面の再現率 0.9 以上・残した場面のうち山のある場面の割合 0.8 以上

### G2 · 取り込み — 済

- OBS の複数音声トラックを、トラックごとの音源(ゲーム音・マイク・Discord)に分ける。ゲーム音は文字起こし・話者の判定に使わない
- Craig の話者別ファイル(`1-名前.flac` など)を、その人のマイクとして扱う
- 顔カメラの別ファイルを音で同期し、ワイプとして常に出す(ゲーム画面の文字の少ない隅へ)

### G3 · テロップと画面 — 済

- 実況向けの発言テロップの既定(大きく派手な型。自分で作った見た目も選べる。済)
- ゲーム画面の文字(HUD・ミニマップ・体力)を避けて置く

### G4 · ショート — 済

- 見どころの上位から 15〜60 秒の縦型を複数本。ゲーム画面を中央で切り、顔カメラを上に置く

### G5 · 配信アーカイブの軽い整え — 済

- 場面は落とさず、長い無言・ロード・離席だけ詰める(方針「軽く整える」: 3 秒を超える無言を 1 秒に詰める)。
  話しながらのロード画面は残す(実況の一部)。声の無いロード・離席は無言として詰まる

### G6 · 実素材での確認 — 済

- 実際の実況の録画で全工程を通す。公開の Dark Souls II 実況(18 分 47 秒・OBS の 1 本・ドイツ語)を
  アプリで「ゲーム実況・面白い所だけ」に通し、本編 6 分 07 秒・縦型ショート 3 本・書き出しまで確認(2026-10-07)
- 見つけて直したこと: 小さな AI がほとんどの場面を「見どころ」にすると詰まらない(点数の判定に置き換える)、
  音声認識の繰り返しの暴走がテロップになる(捨てる)
- この素材で確かめられないもの(顔カメラの別ファイル・OBS の音声トラック別・Craig のコラボ)は、
  合成の素材の結合テスト(`gameTracksReal`)で確かめる
