## 0. 前提: この本が扱う数字と、扱わない数字

この本で使う数字は、**誰でも見られる公開データ**から計算したものだけである。

| 使う(公開データ) | 使わない(所有者だけが見られる) |
| --- | --- |
| 再生数・尺・公開日時 | クリック率(CTR) |
| チャンネルの登録者数・総再生数・本数 | 視聴維持率・平均視聴時間 |
| 急上昇の一覧・検索結果 | インプレッション・トラフィックソース |
| 外部のニュース・予定(出典付き) | 視聴者の年齢・地域 |

右の列は YouTube Studio でしか見られない。**この本は右の列を推測で語らない。** 代わりに左の列だけで、次の3つに答える。

1. **自分の平常はどこか**、どの動画がそれを超えたか
2. **競合はどうか** — 自分以外のチャンネルにも同じ計算をかける
3. **外で何が起きているか** — 発売日・アップデート・大会は、チャンネルの中のデータには無い

右の列が必要なとき(維持率の谷を見たい、サムネのA/Bを比べたい)は、YouTube Studio を開くこと。両方を持って初めて全体が見える。

## 1. 伸びるとは何か — 「平常運転」と「平常比」

### 1-1. 再生数の絶対値を見るのをやめる

「10万回いった」は、それだけでは何も言っていない。**平常が50万回のチャンネルなら大外れ、平常が1万回なら大当たり**である。同じ理由で、他人の再生数と自分の再生数を直接比べても、何も分からない。

見るべき数字は2つ。

- **平常運転** — 公開から14日以上経った動画の再生数の**中央値**
- **平常比** — その動画の再生数 ÷ 平常運転(1.00倍が平常)

平常比で見ると、「10万回」は 0.2倍か 10倍か、どちらかに決まる。以降この本では、動画の成績を必ず平常比で語る。

### 1-2. なぜ「中央値」で、なぜ「14日」か

**平均ではなく中央値**を使うのは、1本の大当たりに全体を引きずられないため。平常 1万回のチャンネルが1本だけ100万回を出すと、平均は約 10万回に跳ぶ。その「平常」に対して、他の全動画が 0.1倍の大不振に見える。中央値なら 1万回のまま動かない。

**14日**は、動画がひとまず落ち着くまでの目安。出したばかりの動画は、まだ伸びている途中である。それを平常の計算に混ぜると平常が低く出て、過去の動画が軒並み「平常より回った」ことになる。だから、14日未満の動画は基準に入れず、平常比も出さない。

> 出して3日の動画を「伸びなかった」と判断して次を変えるのが、いちばん多い判断ミスである。**14日待つ。**

### 1-3. ショートと長尺は別の競技

ショートの再生数と長尺の再生数は、桁が違うことがふつうにある。混ぜて1つの平常を作ると、長尺が一律「不振」、ショートが一律「当たり」になる。

**形式ごとに平常を持つ。** ショートの平常、長尺の平常、その2つの比を見る。「ショートは長尺の30倍回るが、登録には繋がらない」のような判断は、2つを別に持っていて初めてできる。

### 1-4. 「速度」で今を測る

再生数は時間とともに増える。**3日前に100万回の動画と、6時間前に30万回の動画**では、今伸びているのは後者である。今を測るときは「再生数 ÷ 公開からの経過時間」(再生数/時)を使う。

ただし公開直後は分母が小さすぎて跳ね上がる(10分で1000回 = 6000回/時)。だからアプリでは分母に **6時間の下限**を置いている。数字を見るときも、6時間以内の動画の速度は割り引いて読むこと。

### 1-5. 標本が足りないときは「分からない」と言う

4本しかないのに中央値を出すと、たまたまの1本がそのまま「平常」になる。曜日ごとの成績を2本で語ると、金曜に1本当たっただけで「金曜が強い」という法則ができる。

**本数が足りないときは、数字を出さない。** アプリは基準に4本、曜日に3本、タイトルの型に両側4本を要求し、足りなければ「測定不能」と表示する。「測定不能」は失敗ではない。**まだ判断できる段階にない**という、正しい答えである。

### アプリでやること

- **チャンネル分析**タブに自分のチャンネルのURLを貼る → 平常運転(長尺/ショート)・平常比の一覧・「まだ伸びている途中の動画」が出る
- 「平常より回った動画」と「届かなかった動画」を、**タイトルではなく中身**で見比べる(何を撮ったか、どこで切ったか)

## 2. 何を撮るか — 題材の選び方

### 2-1. 題材は4つの軸で見る

「流行っているゲームを撮れ」は正しいが、粗すぎる。同じ「流行っている」にも、次の4つがあり、それぞれ意味が違う。

| 軸 | 何を見るか | 高いと何が言えるか |
| --- | --- | --- |
| **勢い** | 動画の再生速度(再生数/時)の中央値 | 今この瞬間に見られている |
| **新しさ** | 一番新しい動画の経過時間 | まだ出尽くしていない |
| **広がり** | 何チャンネルが出しているか | 特定の1人ではなく、題材そのものが強い |
| **ショート適性** | 直近2週間にショートが実際に何本・どれだけ回っているか | ショートで撮っても回る |

アプリの**ゲームリサーチ**はこの4軸を100点に配分(40/25/20/15)して順位を出す。**順位だけを見ずに、内訳を見る。** 同じ70点でも「勢い満点・広がり0点」と「全部そこそこ」では、撮り方が違う。

### 2-2. 「1チャンネルの独走」を流行と見誤らない

急上昇に同じゲームが5本並んでいても、**全部同じチャンネル**なら、それは「そのゲームが流行っている」ではなく「そのチャンネルが強い」である。真似して同じように回る根拠がない。

だから「広がり」はチャンネル数を本数より重く見る。**1チャンネルだけなら0点**。自分で判断するときも、「何本出ているか」の前に「何チャンネルが出しているか」を数える。

### 2-3. 長尺で流行っていても、ショートで回るとは限らない

急上昇の一覧は長尺が大半で、そこに出た題材がショートでも回るとは限らない。逆に、ショートでだけ回っている題材もある。

**撮る形式で裏を取る。** ショートを撮るなら、その題材のショートが直近で何本あり、どれだけ回っているかを確かめる。アプリの「裏取り」はこれを YouTube 検索でやっている。0本なら、どれだけ急上昇に出ていても「今日ショートを撮るなら」の1位にはしない。

### 2-4. カレンダーを持つ — 外の出来事が題材を決める

発売日・大型アップデート・シーズン開始・大会・コラボ・季節行事。**これらはチャンネルの中の数字には存在しない**が、次に何が伸びるかはほぼこれで決まる。

- **発売・アップデートの前**: 予習・予想・比較(検索が立ち上がる前に置いておく)
- **当日〜3日**: 一番早い体験・検証(速度勝負。編集を軽くして間に合わせる)
- **1〜2週間後**: まとめ・攻略・やり込み(残る動画。検索で長く回る)

アプリの**チャンネル分析**は、Google 検索で自分の題材に関する直近の出来事と今後2〜4週の予定を調べ、**出典付き**で出す。出典を必ず開いて日付を確かめること。**日付が確認できないものは予定に入れない。**

### 2-5. 自分の当たりと、外の出来事を掛ける

企画は「自分の実測 × 外の出来事」の掛け算で決める。

- 実測だけ → 「前に回ったやつをもう一度」になり、擦り減る
- 外の出来事だけ → 自分のチャンネルの視聴者が見ない題材に飛びつく

**両方に根拠がある案から先に撮る。** アプリの企画案には「根拠にした自分の動画」と「根拠にしたニュース」が別々に表示される。片方しか無い案は、優先度を1つ落とす。

### アプリでやること

- **ゲームリサーチ**: 「最新トレンドを分析」→ 順位の**内訳**を開いて4軸を読む → 裏取りの本数を確認
- **チャンネル分析**: 「外部のニュース・トレンドも調べる」を ON → ニュースの出典を開いて日付確認 → 企画案のうち、実測とニュースの両方に根拠があるものを選ぶ
- 「取得元データ」の動画を数本、実際に開いて見る。**数字は方向を教えるが、何を真似るかは見て決める**

## 3. いつ出すか — 頻度・曜日・時刻

### 3-1. 頻度は「直近90日」で考える

「これまで200本出した」は、いまの頻度を何も語らない。半年止まっていたチャンネルの全期間平均は、いまの実態と関係がない。**直近90日で何本出したか**だけを見る。

頻度を上げる前に、平常比を見る。**本数を増やして平常比が下がる**なら、量が質を食っている。逆に、頻度を落として平常比が上がるなら、その方が総再生は増えることがある。

### 3-2. 曜日・時刻は「自分の実測が3本揃ってから」

一般論として「金曜の夜が強い」「休日の朝が強い」などが語られるが、**それは一般論であって自分のチャンネルの話ではない**。視聴者が学生か社会人か、国内か海外かで全部変わる。

自分の曜日別の平常比を見る。ただし**1つの曜日に3本以上揃うまでは数字を信じない**(1-5)。アプリは3本未満の曜日を「—」と表示する。「—」の曜日を「弱い曜日」と読まないこと。まだ測っていないだけである。

### 3-3. 速度勝負の題材は、頻度の枠を破ってよい

2-4 の「当日〜3日」の題材は、決めた投稿曜日を待ってはいけない。**出来事の速度に合わせる。** 週2本の枠は平常時の枠であり、外の出来事が来たときはその日に出す。

### アプリでやること

- **チャンネル分析** → 「投稿頻度(直近90日)」と「伸びの推移」を見る。頻度を変えた時期と平常比の変化を突き合わせる
- 「効いている型」の曜日の欄で、3本以上ある曜日だけを読む

## 4. どう見せるか — タイトル・サムネイル・冒頭2秒

### 4-1. タイトルの型は、自分の実測で検証する

「タイトルに数字を入れると伸びる」は一般論である。自分のチャンネルでそうかは、**数字入りと数字なしの平常比を比べれば分かる**。アプリの「効いている型」は、次の型について「あり/なし」それぞれの平常比の中央値を出す。

- 数字が入っている
- 【】で括りがある
- 問いかけで終わる
- ！を使っている
- 「」でセリフを引いている
- タイトルが長い(25文字以上)

**両側4本以上揃った型だけが表示される。** 表示された型で「あり」が「なし」を明確に上回っていれば、それは自分のチャンネルで効いている型である。一般論より、自分の実測を優先する。

### 4-2. フック手法を知る(語彙として持つ)

急上昇のタイトルを分解すると、フックの手法はいくつかに分類できる。語彙として持っておくと、自分のタイトルを書くときに「どの手で行くか」を選べる。

| 手法 | 何をしているか | 例の形 |
| --- | --- | --- |
| 数字訴求 | 具体的な数で規模・難度を示す | 「○○を100回やったら」 |
| 疑問形 | 答えを知りたくさせる | 「なぜ○○は○○なのか？」 |
| 意外性の提示 | 常識とのズレを見せる | 「○○なのに○○」 |
| 共感訴求 | 視聴者の経験に寄せる | 「○○した人だけ分かる」 |
| 煽り文句 | 感情を先に立てる | 「○○がヤバすぎた」 |
| 検証・実験 | 結果を見たくさせる | 「○○は本当に○○なのか検証」 |

アプリの**ゲームリサーチ**は、急上昇の実際のタイトルをこの観点で分類して「バズる要素」として出す。**分類された例のタイトルは、取得した原文そのもの**なので、そのまま構造を借りられる。

### 4-3. サムネイルは「傾向を知って、外す」

伸びている動画のサムネイルには傾向がある(配色・構図・文字入れ)。アプリはそれを画像から読み取って3項目で出す。

ここで2つの使い方がある。

1. **傾向に乗る** — 視聴者がそのジャンルで「見慣れた」形にする。安全。
2. **傾向から外す** — 一覧の中で目立つ。危険だが、当たれば大きい。

どちらを選ぶかは自分の平常比で決める。**平常比が安定して1.0を超えているなら、外す実験をしてよい。** 不振が続いているときに外すのは、原因を増やすだけである。

### 4-4. ショートの冒頭2秒

ショートは最初の2秒で残るか決まる、と一般に言われる。これを実測で確かめることはできない(維持率は公開データにない)が、作り方として次は守る。

- **結論か、一番強い絵を先頭に置く。** 導入・挨拶・タイトルコールは切る
- **テロップは1行目から出す。** 音を出せない環境で見ている人が多い
- **YouTube のUI(いいね・コメント・チャンネル名)にテロップを重ねない。** アプリのプレビューは実際のショートUIを重ねて表示できるので、重なっていないか確認する
- **無音・言い淀みを切る。** アプリの無音カット・フィラーワードカットを通す

### アプリでやること

- **チャンネル分析** → 「効いている型」で自分に効く型を確認
- **ゲームリサーチ** → 「バズる要素」の例のタイトルから構造を借りる、「サムネイルの視覚傾向」を読む
- **投稿準備**タブ → テロップとサムネ候補から、フック手法別のタイトル案を生成し、4-1 の実測に合う型を選ぶ
- プレビューで **YouTube Shorts UI を重ねて**、テロップが隠れないか確認

## 5. どう作るか — このアプリでの制作手順

数字を見て決めた企画を、最短で動画にする手順。速度勝負の題材(2-4)ほど、この手順を崩さないことが効く。

### 5-1. 標準の流れ(ショート1本)

```
素材を入れる
  └ メディアパネルへドラッグ&ドロップ(複数可)
ハイライトを見つける
  └ AIハイライト自動検出 / 複数素材から自動ラフカット(目標尺に収める)
切る
  └ 無音区間の自動検出→カット / フィラーワード検出→カット
テロップを入れる
  └ 自動テロップ生成(オフライン音声認識) → スタイルはプリセットから
  └ 単語ごとのハイライト(カラオケ字幕)は、テンポの速い実況に効く
音を整える
  └ BGM(Jamendo) + キーワード連動SE(辞書に語を登録しておく)
  └ BGMオートダッキング ON → 声が埋もれない
  └ ラウドネス正規化 ON(-14 LUFS) → 他の動画と音量が揃う
確認する
  └ Shorts UI を重ねたプレビューでセーフエリア確認
書き出す
  └ 9:16 / 1080p。バッチ書き出しで複数解像度を一度に
投稿準備
  └ タイトル案(フック手法別)・概要欄・ハッシュタグ・固定コメントを生成 → コピー
```

### 5-2. 長尺から切り出すとき

長尺の実況から複数のショートを切り出す場合は、**長尺ショート化**の機能を使う。ハイライト候補を出し、目標尺に収まる範囲を選ぶ。切り出しは「その場面だけで意味が通るか」で選ぶこと。文脈が要る場面は、テロップ1行で前提を補う。

### 5-3. 速度勝負のときの省略

当日〜3日の題材で速度を優先するときは、次の順で省く。

1. サムネの文字入れを1語にする
2. BGMを省く(SEと声だけにする)
3. テロップのアニメーションを省く(フェードインのみ)
4. **テロップ自体と無音カットは省かない** — 音を出せない環境の視聴者を最初の数秒で失う(経験則。自分の平常比で確かめること)

### 5-4. AIおまかせ全自動編集の位置づけ

素材を入れて目標尺と方針を書くだけで、ハイライト選定・テロップ・SE・BGMまで一気に組む機能がある。使い方は2つ。

- **下書き**として使い、人が直す(標準)
- **速度勝負のとき**、そのまま出す(5-3 の省略を自動でやっているに近い)

いずれの場合も、出す前に**冒頭2秒**(4-4)だけは自分の目で見る。

## 6. どう振り返るか — 週のルーチン

数字は溜めてから見ても意味が薄い。**決まった曜日に、決まった順で**見る。

### 月曜 — 実測を見る(15分)

1. **チャンネル分析**を回す(自分 + 競合2〜3)
2. 「平常より回った動画」「届かなかった動画」を中身で見比べ、**仮説を1つだけ**書く(例:「検証系が回っていて、雑談系が落ちている」)
3. 競合比較の「登録者あたりの再生」で、自分の位置を確かめる
4. 外部ニュースの予定を、自分のカレンダーに写す(出典を開いて日付を確認してから)

### 撮る前 — 題材を決める(10分)

1. **ゲームリサーチ**を回す(裏取り ON)
2. 順位の内訳を見て、4軸のどれで上位なのかを読む
3. 月曜の仮説とニュースの予定に合う題材を1つ選ぶ
4. 「取得元データ」の上位を2〜3本、実際に見る

### 出したあと — 待つ

- **14日待つ。** それまでの数字で判断しない
- ただし**速度**だけは見てよい。公開6時間以降の再生数/時が、過去の動画の同時点より明確に速ければ、続編を前倒しする

### 月に1回 — 型を見直す

- 「効いている型」で、あり/なしの差が大きい型を確認し、タイトルの書き方を1つ変える
- 曜日別で3本以上揃った曜日が増えていれば、投稿曜日を見直す
- 「伸びの推移(直近90日 vs 前の90日)」が 1.0倍を割っていたら、月曜の仮説を疑う

## 7. やってはいけないこと

すべて、実際によく起きる判断ミスである。

| やってはいけないこと | なぜ | 代わりに |
| --- | --- | --- |
| 出して3日の動画を「伸びなかった」と判断する | まだ伸びている途中 | 14日待つ。速度だけ見る |
| 再生数の平均で語る | 1本の当たりに全体が引きずられる | 中央値(平常運転)で語る |
| ショートと長尺を1つの基準で測る | 桁が違うので片方が一律「不振」になる | 形式ごとの平常を持つ |
| 2本で「金曜が強い」と決める | 1本の当たりが法則になる | 3本以上揃うまで「分からない」 |
| 全期間の平均で頻度を語る | 止まった時期・再開した時期が混ざる | 直近90日 |
| 同じチャンネルの5本を「流行」と読む | そのチャンネルが強いだけ | チャンネル数を数える |
| 急上昇の長尺を見て、ショートを撮る | ショートで回る保証がない | 裏取り(ショートの本数と速度) |
| 取れない指標(CTR・維持率)を推測で埋める | 根拠のない数字で判断することになる | YouTube Studio で見る |
| AIに数を数えさせる | 件数・比較は生成AIが最も落としやすい | 数はコードが計算し、AIには解釈だけを書かせる(このアプリの設計) |
| 出典を開かずにニュースを予定に入れる | 日付が違うと全部が狂う | 出典を開いて日付を確認 |
| 不振のときにサムネの傾向から外す | 原因が増える | 安定してから外す実験をする |

## 8. 付録 — 用語集・チェックリスト・早見表

### 8-1. 用語集

| 用語 | 定義 |
| --- | --- |
| **平常運転** | 公開から14日以上経った動画の再生数の中央値。形式(ショート/長尺)ごとに持つ |
| **平常比** | 動画の再生数 ÷ 同じ形式の平常運転。1.00倍が平常 |
| **成熟** | 公開から14日以上経っていること。成熟していない動画には平常比を出さない |
| **速度** | 再生数 ÷ 公開からの経過時間(時)。分母には6時間の下限 |
| **勢い / 新しさ / 広がり / ショート適性** | ゲームリサーチの4軸(40/25/20/15点) |
| **裏取り** | 候補の題材について、直近14日のショートを YouTube 検索で数え直すこと |
| **登録者あたりの再生** | 平常運転 ÷ 登録者数。規模の違うチャンネルどうしを比べる数字 |
| **伸びの推移** | 成熟済みの動画を、直近90日とその前の90日で比べた中央値の比 |
| **測定不能** | 標本が足りず、数字を出すと誤る状態。失敗ではない |

### 8-2. 投稿前チェックリスト

- [ ] 題材は「自分の実測」と「外の出来事」の**両方**に根拠があるか
- [ ] ショートなら、その題材のショートが直近で回っている(裏取り)か
- [ ] タイトルは、自分に効いている型(4-1)に合っているか
- [ ] 冒頭2秒に、結論か一番強い絵があるか
- [ ] テロップが Shorts UI に重なっていないか
- [ ] 無音・フィラーワードを切ったか
- [ ] ラウドネス正規化とダッキングを通したか
- [ ] 概要欄・ハッシュタグ・固定コメントを用意したか
- [ ] 出した日を記録し、**14日後に見る**予定を入れたか

### 8-3. 数字の読み方 早見表

| 見た数字 | 読み方 |
| --- | --- |
| 平常比 1.5倍以上 | 当たり。**中身のどこが違ったか**を書き残す |
| 平常比 0.7倍以下 | 不振。題材・冒頭・タイトルのどれかを疑う。1本では決めない |
| 平常比 — (未成熟) | まだ判断しない |
| 伸びの推移 1.0倍未満 | 直近90日が前より落ちている。月曜の仮説を疑う |
| 登録者あたり 競合より低い | 登録者に届いていない。投稿頻度か題材のブレを疑う |
| 曜日 — | まだ3本揃っていない。弱いのではない |
| ゲームリサーチで広がり 0点 | 1チャンネルの独走。真似しても回る根拠がない |
| 裏取り 0本 | その題材のショートは直近で見つからない。ショートで撮る根拠がない |
| 測定不能 | 標本不足。本数を増やしてから見る |

### 8-4. この本の数字の出どころ

この本に出てくる数字の定義(14日・4本・3本・6時間・90日・40/25/20/15点)は、すべてアプリの計算と同じである。定義を変えたい場合はアプリ側の定数を変え、この本も合わせて直すこと。

- 平常運転・平常比・成熟・曜日・型・伸びの推移 — `src/renderer/src/lib/channelAnalytics.ts`
- 速度・ショート判定 — `src/renderer/src/lib/videoMetrics.ts`
- 4軸のスコア・裏取り — `src/renderer/src/lib/gameResearch.ts`

数字の正しさは `tests/lib/` の各テストで固定してある。**この本が言っていることと、アプリが出す数字は、常に一致する。**
