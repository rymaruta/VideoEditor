# 実機での確認手順(Windows・RTX 5090)

開発環境(Linux・GPU なし)では全工程を通して確かめたが、次の項目は**利用者の PC と本物のロケ素材**でしか確かめられない。
上から順に進め、最後に「処理の記録」を送ってもらえれば、記録をもとに調整する。

## 1. インストール

1. リポジトリのブランチ `claude/video-editing-app-ivwvqp` を取得し、`npm install` → `npm run build:win`
2. `dist/video-editor-1.0.0-setup.exe` を実行してインストールする
3. 起動できること(初回は「ファイル > 新しい回を作る…」から始める)

## 2. 1本目: 本物のロケ素材で自動編集を通す

1. 「ファイル > 新しい回を作る…」で収録フォルダ(カメラ・ピンマイクのフォルダが入った親フォルダ)を選ぶ
2. ピンマイクに出演者の名前、カメラに「主に映す人」を入れる
3. 番組素材フォルダ(`SE/` `BGM/` `CG/`)があれば指定する
4. 「作成」を押し、全工程が終わるまで待つ(初回だけ AI・文字起こしのモデルをダウンロードする)

確かめること:

| 項目 | 期待 | 開発環境での実測 |
|---|---|---|
| 同期 | 全カメラ・全マイクが「同期」になる | テスト素材で 4/4 |
| 使った装置 | 自動編集の「ログ」に AI の装置が CUDA と出る(書き出しの進み具合には「GPU: NVENC」と出る) | GPU なしのため未確認 |
| 文字起こしの時間 | 収録の長さより十分短い | CPU で 30分の収録に 20分 |
| 構成の判定 | 「AI(Qwen2.5 14B・CUDA)」で判定される | CPU では 1.5B のみ |
| 笑い・歓声 | 笑いの多い場面に「笑い ○」が付く | テスト音声で検出 |
| 発言テロップ | 話者の取り違え・誤字が少ない | テスト音声で CER 8.3%・話者 24/24 |

## 3. 画面の操作

- プレビューを再生し、カメラが切り替わる所で止まらないこと
- タイムラインの離れた位置をクリックして、**0.1 秒前後で画が出る**こと(開発環境では Linux の書体の問い合わせで 1〜2 秒かかることがある。Windows では起きない見込み)
- 要確認の一覧から「移動」「直す」が動くこと

## 4. 書き出しと自動確認

1. 「書き出し…」で 1080p(必要なら 4K)を選んで書き出す
2. 書き出し後の自動確認で、ラウドネスが配信向け −14 LUFS 付近になること、黒味・フリーズ・無音の指摘が妥当であること

開発環境の実測: 24分36秒の本編を CPU(x264)で 8分33秒、自動確認は問題なし・−14.0 LUFS。

## 5. 過去回から学ぶ・人の完成版と比べる

1. 新しい回の画面の「過去回から番組スタイルを学ぶ」で、Premiere から書き出した過去回の XML を選ぶ
2. 自動編集の「構成」タブ「人の完成版と比べる…」で、同じ回の完成版の XML を選び、採用区間の一致度(IoU)を見る
3. マルチカメラのまま書き出した XML は、アングルの比較だけ外れる(Premiere で「マルチカメラ > 統合」してから書き出すと比べられる)

## 6. 送ってほしいもの

- 自動編集の「ログ」タブの「処理の記録を保存…」で保存したテキスト(工程ごとの時間・使った装置・PC の構成が入る)
- 気になった場面があれば、そのタイムコードと内容
- (可能なら)Premiere の XML: マルチカメラのまま書き出したもの1本
