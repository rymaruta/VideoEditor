# tests/ — 何を、どこまで厳しく確かめるか

`npm test` で全部走る（数秒）。`npm run build` の中でも走るので、**落ちるテストを
残したままビルドは通らない**。1本だけ回すなら `npx vitest run tests/lib/captionRows.test.ts`。

## なぜコミットするのか

以前は確認用のコードをスクラッチパッドに書いては消していた。速いが、**直したはずのものが
次の週に戻っても誰も気付かない**。バグ狩りで測った数字は、記録に書くだけでなく
ここに期待値として置く。

## 置き場所

| ディレクトリ     | 対象                                                             |
| ---------------- | ---------------------------------------------------------------- |
| `tests/shared/`  | `src/shared/**` の共有ルール（画面と書き出しが両方使う数字と式） |
| `tests/lib/`     | `src/renderer/src/lib/**` の純関数                               |
| `tests/store/`   | `projectStore` の不変条件・履歴・リンク追従                      |
| `tests/main/`    | `src/main/**` の純関数（ffmpeg を起動しないものだけ）            |
| `tests/helpers/` | 境界値の一覧と固定種の乱数                                       |

**ffmpeg も DOM も持ち込まない。** 実機での確認は xvfb と ffprobe の役目で、
その結果は `docs/BUGHUNT.md` に数字で残す。ここは**その数字を固定する場所**。

## 1つの関数につき書く5種類

1. **ふつうの入力** — 仕様どおりの値と期待値。数値ものは理論値と一致する数字で。
2. **境界値** — 0・空・最大・負・NaN・±Infinity。`helpers/boundary.ts` の
   `NASTY_NUMBERS` / `NASTY_VALUES` を回す。
3. **不変条件（プロパティ）** — 「必ず 0〜1」「終わりは始まり以上」「同じ段に重なりが無い」
   のように入力によらず成り立つことを、`seeded()` の**固定種**で作った乱数数千通りに当てる。
   種を固定してあるので、落ちたら必ず同じ手順で再現できる。
4. **`【レグレッション】`** — バグ狩りで直したもの。見出しに日付を付け、
   `docs/BUGHUNT.md` の実測値をそのまま期待値にする。修正前の数字はコメントに残す。
5. **`【既知の穴】` / `【既知の限界】`** — 測って「いまは直さない」と決めたもの。
   **いまの挙動を固定する**（`BACKLOG.md` の候補にも積む）。直すとここが落ちるので、
   直し忘れも、直したのに記録し忘れることも防げる。

## 計器を先に疑う

期待どおりの結果が出たときほど、テスト側の間違いを疑う。**まず「変わるはずのものが
変わる」対照を1つ取り**、それが動いてから本題を測る。

この方針を入れた回だけで、次の4件が計器の間違いだった:

- 画像の指紋に **PNG のヘッダ**を使っていて、どの画像でも同じ値だった
- 検査用の音が**一定の正弦**で、範囲を変えても波形の絵が本当に同じだった
- 丸めヘルパー自身が**桁あふれ**して、有限の入力から無限を返していた
- `addTextOverlay` は**オブジェクト**を取る API なのに文字列を渡していた
  （開始も終了も `undefined` のテロップが 152/200 ラウンドで生まれ、本物のバグに見えた）
